# Animal lifecycle — milestone 3.6

**71 BUY_ANIMAL: BLOCKED.** Previously the handler accepted any two bytes regardless of owner or farm context, emitted a success packet with zero balances and added an invented animal only to RAM. It now responds with an explicit temporary-unavailable dialog and makes no purchase or balance change. This intentionally changes the existing behavior; no runtime switch or fabricated price was added. It applies to every deployment using this commit. The regression exercises request before farm entry and after joining the owner's farm, repeated requests, unchanged balances/list and no success packet. The fix eliminates this purchase path, but is not a playable animal lifecycle.

Native 2.5.8 `it.a(ad,int)` sends byte species and byte currency; decoder `kz` dispatches 71 and parses its success response. Unity uses two display prices, for xu and lượng, and its `FarmData` parses species, display price, harvest time and product price. This does not establish the authoritative server price, currencies and restrictions, capacity or initialization; no target transaction source was found in the examined sources. Before enabling paid purchases obtain an authoritative target catalog and server rules, approve the resulting policy, then atomically persist currency and farm data under revision checks and verify restart, concurrent/duplicate requests and native UI.

**72 PRICE_ANIMAL: BLOCKED.** Native 2.5.8 sends int farm ID plus byte index. Price and sale policy remain unknown. **74 HARVEST_ANIMAL: BLOCKED.** Its native request also sends farm ID and index, but output quantity, product identity, maturation, health, storage and replay rules are unverified. **79 INFO_ANIMAL: BLOCKED.** It is an observed server-to-client state update, not a verified request.

Unity's `readInfoAnimal` interprets the fields as int bornTime, byte health, byte harvest percentage, byte egg count and three booleans for hunger/diseases. Current `FarmService.writeInfoAnimal` instead writes int health, byte level, byte resourceCount, byte nextProductionTime and booleans alive/breeding/harvestable. The legacy persisted JSON names match the latter model. This mismatch is a reason not to claim a verified read-only status flow or migrate saved data without target-version mapping and authoritative lifecycle rules. No native acceptance of these fields was performed in 3.6.

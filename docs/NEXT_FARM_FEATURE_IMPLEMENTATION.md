# Next farm feature — milestone 3.4

**MATERIALLY ADVANCED, NOT IMPLEMENTED.** Native client decoder `kz` dispatches 78 to read `byte cellIndex`, `byte cropId` and the same cell-state decoder used by JOIN, followed by a local rendering update. It dispatches 79 to read `byte animalIndex`, `byte animalId` and animal-state data, followed by a rendering update. The `it` farm request builder has no corresponding command 78 or 79 emission; this establishes these decoder branches as incoming updates, not proof that arbitrary request handlers are useful. The decoded cell state is `short ageMinutes`, two bytes and three booleans; the specific business meanings of all flag fields remain unverified.

The client does construct command 65 as `int farmId, byte index, short itemId`, but verified effect, consumption, limits and response semantics are still missing. Command 74 similarly needs authoritative animal production and persistence rules. No new writable gameplay feature was enabled from incomplete evidence. A useful next step is to identify an actual client action and target-owned rule for care, then test its ownership, atomic persistence and client response end to end.

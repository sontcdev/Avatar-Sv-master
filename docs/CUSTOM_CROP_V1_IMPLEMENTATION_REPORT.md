The feature defaults OFF. Enabling it requires an independently provisioned, owner-only identity file and matching single-row marker in the explicitly named disposable `avatar2d_customcrop_test` database. Startup rejects missing or mismatched identity and mappings, and only `synthetic-test` mode is accepted. This fixture gate is not authorization for native deployment; physical isolation depends on provisioning the test database and identity. Keep the file and marker secret and provision them independently of ordinary JVM flags.

For the full-server smoke, a private MariaDB instance used schema from the project SQL dump and its compatibility/migration scripts. Only selected static catalog rows were imported; no existing account or character data was imported. The empty `settings` table uses application defaults. An unauthorized enablement without an identity failed closed. Early command 66 returned rejection, and a comparison of the persisted crop and inventory showed no mutation.
